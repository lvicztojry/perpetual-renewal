## 一 施工边界与开工规则

### 产品范围

- 覆盖应用 Web、Windows 本地客户端、Android 本地客户端，共用课程定义与引导引擎，分别验证运行环境。
- 首次主线覆盖初醒、界面认识、留灯会、创建人物、第一次聊天、入梦基础和收尾；其余功能提供可独立进入的小课程。
- 保留旧城、巨钟、余念安、留灯会、生生不息和入梦的既有二创设定。只增加衔接、动作、对白和用户行为反馈，不新增仙法或改写核心世界观。
- 不把普通聊天变成评价或校准界面；语气校准继续发生在入梦。
- 默认复用现有余念安立绘和轮廓兜底素材。新立绘、配音、视频、复杂骨骼动画不作为本轮依赖。
- macOS、iOS、微信小程序暂停扩展；保留既有代码。本轮不包含公开部署、推送、合并、发布安装包或变更公开下载。
- 不引入新的远程分析服务、AI 剧情生成请求、付费依赖或全局状态管理框架。教程文案使用本地配置；业务操作继续调用既有业务接口。

1. 阅读本文、`docs/CONTRIBUTING.md`、`docs/MVP_STATUS.md`、`docs/TASKBOOK.md`，以及当时实际存在的适用 AGENTS.md。入梦、记忆、群聊、语音任务另读对应专题。
2. 运行 `git status --short`，记录已有变更。编制本文时，工作区已有语音、原生构建、测试和管理文档等未提交改动，包含 `renewal-workspace.tsx`、`package.json`。以开工时状态为准，不覆盖、回退、暂存或提交他人改动。
3. 由集成负责人认领共享文件；工作代理先领取任务卡再修改。只有用户或适用规则授权并行代理时才启动子 Agent；同一 Agent 也可依次执行全部任务。

6. 本文涉及的新增文件名是建议边界；负责人可小幅调整目录，必须同步引用、保持单一实现，并在交接注明映射。

## 三 用户体验契约

### 视觉与交互

| 项目 | 必须实现的行为 |
| --- | --- |
| 背景遮罩 | 默认深青黑半透明遮罩，建议不透明度 0.45 至 0.60；目标区域保持清晰，不模糊文字或输入内容 |
| 高亮形态 | 按钮或图标用圆形/胶囊光圈，输入框和区域用圆角框；默认 6 至 8px 外扩、2px 描边，暖金色弱辉光 |
| 动画 | 呼吸周期建议约 2 秒；不闪烁，不无限播放大范围动效；减少动态模式改为静态描边 |
| 角色 | 桌面展示不挡目标的余念安半身或立绘；小屏用头像与紧凑对话卡。素材失败切换现有轮廓图，再失败显示姓名与文字 |
| 文案 | 姓名、至多两句剧情对白、一句独立操作指令、当前任务和步骤。默认正文约 14 至 16px，避免大段文字挤压操作区 |
| 目标数量 | 每次只要求一个主要动作；允许给同一表单字段组作说明，但不同时要求点击多个分散目标 |
| 点击操作 | 点击目标后等待对应界面状态或成功结果；不因任意 click 直接完成 |
| 输入操作 | 高亮输入框，用户自行输入或主动采用示例；内容有效后启用“写好了”。不监听首个字符就自动跳步，不在中文输入法组合输入中推进 |
| 结果操作 | 创建、发送、保存、导入、反馈、应用必须等待成功；重复点击沿用业务锁，不引起重复请求 |
| 说明操作 | 仅用于区域介绍，按钮写“知道了”，不登记为已完成业务实操 |
| 退出与暂停 | 任意实操步骤均可“暂歇”或退出。暂停移除遮罩并持久化；收起仅隐藏本次展示，当前挂载期间不得自动再弹 |
| 跳过 | 分开“跳过本节”和“结束本次引导”；保留独立 skipped 结果，不把跳过写成学会 |
| 回退 | 阅读步骤可返回；实操步骤返回只重新讲解，不撤销消息、人物或设置，也不自动重发 |
| 等待 | 业务等待显示真实状态。请求慢时可暂停/退出；教程自身出错不阻断原功能 |

### 布局与可访问性

- 桌面优先把卡片置于目标右侧或下方，空间不足翻转；与目标建议保持至少 12px，不能遮住目标本体或其关键说明。
- 手机依据实际 `visualViewport` 和安全区定位。键盘出现后，输入目标、提交按钮与必要提示仍能访问；必要时将立绘收成头像、对话收成一行提示，可展开阅读。
- 不把原 DOM 克隆成可点击假按钮。高亮真实控件，保留原来的焦点、校验、事件、禁用和可访问名称。
- 强指引步骤只允许目标、教程控件和必要滚动区域交互；必须同时限制鼠标/触摸与键盘访问，不能只用视觉遮罩。不要将目标所在祖先一起设为 inert。
- 自由教学步骤允许浏览页面；用户切换人物或页面时，暂停当前目标并给出继续入口，不能把后续事件记到原人物。
- 屏幕阅读器能读到步骤和目标说明；用礼貌播报通知步骤变化，不逐帧播报。无需精确看见光圈也能完成。
- 进入步骤时合理设置焦点，避免输入框反复失焦或自动唤起手机键盘；暂停、退出和弹窗关闭后恢复到仍存在的合理控件。
- 点击热区至少 44×44 CSS px；320px 窄屏、200% 缩放不出现横向溢出或退出按钮不可达。

### 弹窗和演出

1. 优先级从高到低：系统权限/登录失效/必须处理的业务确认，钟声与能力演出，教程实操，普通非阻断提示。
2. 教程自身预期打开的创建表单、资料抽屉、入梦确认弹窗，属于教学上下文，不能触发现有“所有 dialog 都阻塞教程”的规则。
3. 为教学弹窗提供显式 host，在当前可交互的原生 dialog 内渲染提示与高亮。普通 body portal 的高 z-index 不能覆盖浏览器 top layer，不采用该方案冒充解决。
4. 使用非阻断的覆盖层或适合的弹窗内结构，避免额外 `showModal()` 让业务表单失去交互。未知弹窗出现则暂让，关闭后校验目标再恢复。
5. 系统权限框不能在 DOM 中画光圈。打开前在相关按钮旁说明，返回前台后重新检测授权与布局；拒绝权限时提供返回、跳过与设置指引。

## 四 主线课程与对白脚本

使用稳定的课程 ID 与步骤 ID，中文显示文案可调整，ID 不随文案改名。主线 ID 为 `main`。每行的箭头表示独立步骤，不能实现为一张介绍卡。

| 章节与步骤前缀 | 操作链与完成条件 | 余念安对白及明确指令示例 |
| --- | --- | --- |
| 初醒 `awakening` | 场景 → 原有三种回答 → 对应回应 → 选择同行或自行探索。回答只影响教程对白 | “我是余念安。灯一直亮着，什么时候来都不迟。”／“点击「带我熟悉这里」，让我陪你走一程。” |
| 旧城 `arrival` | 高亮人物列表 → 聊天区域 → 工具入口，三步均为阅读确认 | “相逢之后，总要有个能找到彼此的地方。”／“这里是人物列表。以后点击名字，就能回到 TA 身边。” |
| 留灯 `lanterns` | 用户点击留灯会入口 → 既有 starter 幂等创建/获取 → 等待群页面注册 → 高亮聊天记录 → 可选问候 → 高亮继续前往创建的入口并由用户点击 | “巷子里有人留着灯。你可以先坐一会儿。”／“点击亮起的入口，去看看留灯会。” |
| 描摹 `creation` | 高亮“想见谁”真实入口 → 关系类型 → 名字 → 称呼 → 性格与语气 → 创建按钮 → 已保存人物成功 | “先写下名字吧，让想念有个可以呼唤的地方。”／“点击「名字」输入框，填写你想见的人的名字。” |
| 回声 `conversation` | 定位所选人物 → 输入第一句话 → 用户确认写好 → 点击发送 → 用户消息持久化 → 等待回复 → 收到回复后剧情回应 | “有些重逢，可以从一句寻常的话开始。”／“点击输入框，写一句想说的话；写好后点击「发送」。”实际拆成输入与发送两步 |
| 入梦 `dream` | 点击入梦入口 → 用户开启梦境 → 演出结束 → 情境输入 → 生成一轮 → 选择或纠正 → 提交反馈成功 → 查看片段 → 变化预览 → 自主应用或保留草稿 | “我们可以慢慢拾起 TA 的语气。”／“点击「梦中情境」，写一句你想听 TA 回应的话。” |
| 此后 `complete` | 回顾已完成与跳过项 → 指向“找余念安” → 打开课程目录 → 结束 | “路已经认得了。以后想问什么，就来找我。”／“点击「找余念安」，随时继续学习或重看这一程。” |

### 主线分支与完成规则

- 初次讲解目标约 5 至 8 分钟，不含自由填写和模型等待。入梦完整练习允许延后，此时主线可收尾，但课程目录明确“入梦实操待继续”，不能写成所有功能已学会。
- 留灯会非强制发送消息。静坐阅读后可以继续；没有发送时只记录了解群聊，不记录发言成功。继续入口可在教程卡中提供导航，但到下一页仍需引导真实创建入口。
- 创建步骤允许保留默认类型和有效字段；示例必须由用户点击采用，且只填空字段。已有输入先保留，覆盖前明确询问。称呼、性格语气可用有效默认值继续，但不能自动断言用户修改过。
- 已有人物的旧用户或重看用户，提供“使用现有人物”和“创建新人物”。使用已有资源属于复习路径，登记 `reused`，不伪造 `companion-created`。
- 首次聊天要区分“用户消息已保存”和“AI 回复已到达”。回复失败保留当前等待/恢复节点，提供业务重试；用户可明确跳过等待继续探索，不伪造收到回复。
- 入梦主线正常完成需要至少一轮生成和反馈成功，并查看变化预览。应用正式设定必须由用户操作业务确认按钮。用户可以取消应用、保留草稿，再明确选择稍后继续；结果为 `practiced` 或 `deferred`，不得写成 `applied`。
- 不强制用户认可某句回声或片段。无合适回声时可纠正；没有可信片段时可只查看说明并继续，不强制勾选。
- 用户选择暂时不想说时，后续对白使用中性称呼。教程不强制填写真实关系或个人往事。
- 章节交接补人物动作和短场景，并响应刚发生的成功操作。例如创建后“纸上的轮廓渐渐有了温度”，聊天后“这封信终于有了回音”。不反复重复开场，不靠大段世界观说明延长时长。

## 五 独立课程完整覆盖表

课程目录至少支持：继续上次、当前页面教学、全部课程、重看剧情。显示未开始、学习中、已实操、已了解、稍后继续、已跳过；这些是展示标签，不与主线账户状态混用。

| 课程 ID | 必须覆盖的操作链 | 前提与结束条件 |
| --- | --- | --- |
| `people` | 人物列表切换 → 人物资料 → 编辑名字/称呼/性格语气 → 保存 → 认识主动回响字段 | 至少一位自有人物；保存后核对实际结果。可选只查看路径 |
| `chat` | 输入/发送 → 发送中与失败重试 → 查看回复 → 重新生成入口 → 消息重要标记和删除说明 | 有人物；重生成由用户自选，删除只解释，不要求删除记录 |
| `memory` | 打开记忆 → 候选与长期区分 → 查看来源 → 用户选候选确认 → 查看纠错和历史 → 归档/遗忘说明 | 有人物；无候选时提供清晰空态，不自动制造真实记忆。实际确认和纠错单独记结果 |
| `material-import` | 选择人物 → 导入素材 → 导入方式与类型 → 输入/选文件 → 核对 → 提交 → 查看结果 | 用户主动选择素材；可选演示文本需显式采用，提交产生真实数据须说明 |
| `chat-character` | 进入聊天记录创建 → 选择记录 → 解析与双方样本 → 提炼 → 编辑预览 → 可选试聊 → 确认创建 | 无记录可用时提供虚构样例路径并标识；用户确认后才创建，不能后台自动上传 |
| `dream` | 对比选择与自由试聊 → 纠正与适用范围 → 片段确认 → 草稿保存 → 变化预览与应用 → 查看历史 → 恢复版本说明 | 有人物；只教版本恢复的查看和确认位置，不强制执行恢复；支持完整主线续接 |
| `groups` | 进入群聊 → 创建/选择群 → 选成员 → 发言 → @成员 → 认识邀请主动发言 → 成员与设置 | 创建需要可选人物；已有群可复习，不重复创建。发送成功、@选择分别记录 |
| `group-memory` | 选择群消息 → 群记忆 → 查看来源 → 指定知情成员 → 核对内容 → 确认 | 有自有群和已保存消息；没有材料就提供返回继续聊天路径；不能扩大默认私聊授权 |
| `voice` | 系统识别与供应商转写说明 → 用户选择路径 → 主动授权 → 开始/停止 → 核对转写草稿 → 自行发送 → 朗读最近回复与停止 | 根据运行环境、权限、引擎、模型分支；不支持则解释和跳过，不冒充成功；供应商路径明确上传 |
| `proactive` | 全局开关 → 人物开关 → 预设/自定义频率 → 安静时段 → 保存 → 区分群主动聊天 | 用户自愿开启；保留原值可完成阅读路径；说明原生后台受系统限制 |
| `model` | 模型供应商入口 → 网关/模型/凭据字段用途 → 已配/未配分支 → 保存 → 连接测试 → 回到原课程 | 不读取或保存教程中的凭据原文；已有 Key 不要求重填；模型连接成功不代表语音模型可用 |
| `preferences` | 资料 → 沟通偏好 → 外观 → 保存或保留当前值 | 教程预览不能隐式覆盖设置；保留当前值记为已了解 |
| `account-data` | 账号入口 → 隐私与导出说明 → 用户自愿导出 → 本地恢复与设备独立说明 → 删除账号风险说明 | Web 与本地适配实际可用项；删除仅讲解，不引导实操，不新增尚不存在的迁移/同步功能 |

每门课必须有前提检查、正常路径、取消/跳过路径、请求失败路径和恢复策略。首次进入某功能时以小提示邀请学习，仅用户接受后进入遮罩教学；同一课程版本被拒绝后不反复打扰，可从目录开启。

“覆盖完整”以开工时页面实际功能为准。JG-01 输出功能清单与本表映射，遗漏入口须加入相应课；高风险操作可用说明步骤覆盖，不能以实现一批通用介绍卡代替实操。

## 六 状态协议与数据设计

### 持久化模型

优先将现有 `UserJourney.state` 和本地 `renewalJourneyStore` 升级为 v2，保留 `revision` 并发机制。由 JG-02 固化精确类型与输入白名单，最低应表达以下信息：

```ts
type CourseResult = "learned" | "practiced" | "reused" | "deferred" | "skipped";

type JourneyStateV2 = {
  version: 2;
  revision: number;
  status: "legacy" | "active" | "paused" | "completed" | "skipped";
  step: JourneyStep; // 保留现有七章 key，主线章节由合法步骤推导
  companionId: string | null;
  activeCourse: {
    id: string;
    contentVersion: number;
    runId: string;
    stepId: string;
    mode: "first" | "review";
    context: { companionId?: string; groupId?: string };
  } | null;
  courses: Record<string, {
    contentVersion: number;
    checkpoint: string | null;
    result?: CourseResult;
    milestones: string[];
  }>;
  deferredCourses: string[];
  dismissedInvites: Record<string, number>; // course ID -> contentVersion
};
```

以上为语义约束，不要求逐字照抄。所有 course/step/milestone ID 受静态课程白名单约束；服务端只接受合法转换。`learned` 表示完成课程要求，不代表所有可选业务都执行过；真实动作依 milestones 区分。

- 不在教程状态存名字、用户输入、聊天、纠正文案、文件内容、Key、录音、DOM 坐标。未保存草稿沿用业务原有机制；原功能不支持刷新保留时，提示重新填写，不在教程另存一份。
- `runId` 绑定本次学习，重看生成新 run；旧请求和旧事件不能推进新 run。切换账户清理所有临时状态、订阅和请求。
- 课程进度与主线进度分开。学习单课不重置七章；剧情回看不重置课程成绩；主线重放不删除业务资源。
- 本地 store 使用既有 codec 与账户隔离通道，不新建全局 localStorage 进度作为事实来源。localStorage/sessionStorage 只保留既有抑制等展示偏好，并按账户隔离新增偏好。
- GET 不创建人物、群或梦境，不修改业务记录。新账号显式初始化；旧账号默认不强制自动进入。v1 兼容读取可内存归一化，在首个合法写操作持久化 v2，避免 GET 副作用。

### 协议动作与证据

保留现有 `start/resume/pause/skip` 的含义；新增课程开始、阅读确认、步骤确认、重看、跳过本课、业务观测等动作时统一白名单。每次写带 `expectedRevision`，课程写另带 `courseId/runId/stepId`。业务事件可带 `resourceId`，重复确认按同一节点与证据去重。

| 类型 | 验证与推进规则 |
| --- | --- |
| 阅读完成 | 当前步骤必须声明为阅读型；只记录了解，不写业务成功里程碑 |
| 输入写好 | 当前表单前端校验通过并由用户确认；可记录本次教学检查点，不将其当持久化业务证据；刷新后重新检查字段 |
| 打开面板/到达页面 | 由当前页面适配器确认目标和上下文；可推进导航步骤，不能完成提交步骤 |
| 创建/保存人物 | 校验资源归属与持久化结果；首次创建必须对应本次操作，不以任意旧人物存在作为新建成功 |
| 消息发送/回复到达 | 校验 conversation、人物和消息 ID；区分用户消息保存与助手回复；回顾使用历史消息须显式选择 reuse，不能误认新回复 |
| 入梦生成/反馈/应用 | 校验对应 dream、round/feedback/version ID 和状态；`dream-started` 仅推进开启节点；预览查看是 UI 事件，应用必须有业务成功证据 |
| 导入/记忆/群操作 | 依据既有响应和持久化数据绑定资源；无可验证服务端证据的 UI 行为不能伪装成服务端验证的业务结果 |
| 同步/冲突 | 409 后先重读，保留业务草稿；只可重试仍合法且幂等的教程确认，不自动重发业务命令。已暂停、已跳过、已换 run 时不补推进 |

页面适配器只发布当前账户与上下文的成功通知，教程协调器串行处理。服务端继续执行所有资源归属校验，不信任浏览器 CustomEvent；请求使用资源 ID 核对，不能仅验证“这个人曾经有一条消息”。必要时保存非敏感业务 ID 作为已接受的证据引用，精确结构由 JG-02 定义。

### 版本兼容与升级矩阵

| 原状态 | 升级行为 |
| --- | --- |
| 无 journey 的旧账号或旧加密快照 | 保持 legacy，不自动弹出，不重新生成初始业务资源 |
| v1 active 的剧情章节 | 映射到同章最接近且可解释的步骤，沿用绑定人物 |
| v1 active 的创建/聊天/梦境 | 先核对现有业务资源，再从安全检查点恢复；不自动重复创建、发送、开启梦境 |
| v1 paused | 升级后继续 paused，用户主动恢复 |
| v1 skipped | 继续 skipped；课程目录可手动开启 |
| v1 completed | 保留已完成标记，新增课显示可学习，不强制补做；旧完成并不伪造成新入梦应用成功 |
| v2 内容版本变化或步骤被移除 | 迁移表映射到最近安全检查点，保留既有结果；不全量重置 |
| 未知更高状态版本 | 安全停止教程写入，展示可关闭的兼容提示，业务继续可用；禁止覆盖未知结构 |

Web 多标签页共享进度；原生账号仍按设备独立，不新增跨设备同步。要明确新旧客户端兼容策略：v1 状态可由新代码读取；旧代码不得用白名单失败后重置 v2。实现完成后回退旧客户端存在格式不兼容风险，交接必须注明；关闭新教程展示不能销毁 v2 数据。

## 七 引导引擎与页面适配契约

建议新增 `src/components/journey/` 存视觉和 hooks，`src/lib/journey/` 存类型、纯状态转换与课程配置。由集成负责人在 JG-01 固定导出，避免各模块各造一套引擎。

### 课程定义

每个步骤至少声明：`id`、`courseId`、`chapter`、`kind`、`targetKey`、`context`、`dialogue`、`instruction`、`completion`、`next`、`fallback`、`interactionPolicy`。kind 至少区分 story/read/navigate/input/action/wait/review；kind 不能代替明确完成条件。

课程配置中不放跨组件任意 DOM 操作脚本。通过页面注册能力调用“打开某面板”“定位某人物”等适配行为，且恢复动作不能触发创建、发送或应用。普通学习应让用户点击真实入口。

### 锚点与注册

建议使用 `data-guide` 配合页面注册表。最低锚点示例：

| 页面 | 稳定锚点 |
| --- | --- |
| 主工作区 | `people-list`、`create-person`、`active-person`、`chat-input`、`chat-send`、`chat-last-reply`、`open-dream`、`open-profile`、`open-memory`、`open-import`、`open-groups`、`journey-entry` |
| 人物表单 | `person-kind`、`person-name`、`person-addresses`、`person-style`、`person-submit` |
| 入梦 | `dream-start`、`dream-situation`、`dream-generate`、`dream-choices`、`dream-correction`、`dream-feedback-submit`、`dream-fragments`、`dream-review`、`dream-apply-confirm` |
| 群聊 | `group-create`、`group-members`、`group-input`、`group-send`、`group-mention`、`group-memory`、`group-settings` |
| 设置 | `settings-model`、`settings-model-test`、`settings-appearance`、`settings-preferences`、`settings-privacy`、`settings-save` |

同一锚点可能在桌面/移动端或 create/edit 中重复，注册必须提供可见性、当前 host、表单 mode、resourceId 与页面身份；只有一个可见且语义匹配的目标才进入强指引。存在歧义时显示可关闭的恢复提示，不任取第一个节点。

适配器至少报告：页面 ready、可用目标、业务上下文、当前弹窗 host、可用能力、成功结果。注册和卸载必须对称；关闭面板、组件重挂和 StrictMode 不能泄漏监听或复用陈旧 ref。

### 定位与失效恢复

1. 导航/打开面板 → 等待对应页面注册与数据 ready → 解析唯一目标 → 必要时滚动最近滚动容器 → 布局稳定后测量 → 展示指引。
2. 使用 ResizeObserver、必要的滚动/窗口/visualViewport 事件和有限范围 MutationObserver；测量以 requestAnimationFrame 合并。不要全页面持续轮询或每次 style 变化全量 setState。
3. 高亮不改变被指引元素的业务布局，不随意提升其 z-index 破坏层叠上下文。可用几何遮罩分片或其他支持真实命中的实现。
4. 监听自身遮罩变化时排除自身，防止现有全局 MutationObserver 与动画互相触发。空闲状态不持续重渲染。
5. 初始等待目标建议最多 5 秒，超时给“重新定位”“返回本节入口”“暂歇”，不自动跳成功。模型生成等待不受 5 秒目标超时误判。
6. 主动切换页面、人物、群或目标删除时立即撤掉旧高亮；提供重新选资源或回到课程入口，不自动创建替代资源。
7. 恢复先加载账户进度，再解析业务上下文。未持久化输入丢失时回到输入步骤，已成功的业务操作即使教程保存失败也通过证据对账接上，不重复操作。

- 验证：课程图无不可达节点、悬空 next 和无法退出的等待；用配置校验辅助发现重复 ID，但必须人工核对教程语义。
- 完成标准：每步都有对白或明确说明及操作指令；短文案适应手机；操作反馈与真实结果相符。

### JG-06 人物创建与私聊主线

负责人：人物私聊 Agent。主要文件：`renewal-workspace.tsx`、`relationship-object-form.tsx`、相关 CSS 与测试。

### JG-07 入梦实操闭环

- 验证：至少一条完整正常路径、一条取消应用保留草稿、一条冲突恢复；确认教学不向正式聊天与长期记忆写入练习内容。

## 十 交付与完成标准

### 每个工作包的交接格式

```text
任务：JG-xx 与本次完成范围
基线：分支/提交或工作区基线，保留的他人变更
改动：文件、行为、公共接口与调用示例

异常：失败/未执行项、复现方式、实际影响

集成：依赖补丁、共享文件待合入片段、接手者下一步
```

任务不能以“已加锚点”“已写配置”“构建通过”独自宣布完成，须满足任务卡的行为完成标准。跨端设备未验不能写成三端全面通过。实际结果由集成负责人登记到 MVP_STATUS，本文不维护第二套实时状态。

### 最终完成条件

1. 用户在真实页面可跟随余念安完成创建、聊天和入梦练习，每一步明确知道点哪里、为何而点。
2. 七章有连贯剧情和行为回应，首轮流程可暂停、跳过和恢复；所有独立课程可从目录进入。
3. 表单、抽屉、原生 dialog、手机键盘、演出、权限和错误不会造成教程消失后无处续接或锁死业务。
4. 主线完成、单课了解、真实实操、复用资源、延后和跳过分别准确记录；不靠路由、点击数或任意历史数据伪造结果。
5. v1 与旧加密快照兼容，进度写冲突和账号切换不丢数据；教程关闭后业务独立可用。
6. 全部任务卡、行为矩阵和课程覆盖表都有实现与验证映射，遗留缺口明确登记；阻断核心路径的缺陷全部修复。
7. 交付代码、验证结果、截图/短录屏及文档；公开发布、线上生效与用户设备确认另行判断。
