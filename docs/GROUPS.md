# 群聊：多人接话与共同记忆

群聊复用已有的人物设定、入梦成果与用户模型供应商；正式消息、共同记忆、成员关系和主动节奏独立保存。

## 使用

从聊天侧栏进入「群聊」，填写群名、背景并邀请自己创建的人物。支持 @ 人物、逐条回复和「正在输入」；用户可以中途发消息，旧轮尚未送出的生成结果不会覆盖新话题。消息发送使用 clientId 防止重试重复发送。

「成员与设置」中配置每位成员的群内关系描述、私聊记忆使用权限和群内主动开关。群总开关、安静时段、分钟间隔、每轮人数、是否自行聊天及连续轮数共同控制主动回响。用户全局主动开关仍生效；群内主动权限与私聊人物开关独立。

共同记忆由用户从群消息中选择来源、编辑内容并确认知情人物。只向知情人物提供该记忆；新成员默认不读加入前的消息。私聊记忆默认不进入群上下文，打开权限时也只读取该人物自己的有效记忆。已确认且该人物知晓的群记忆可用于之后的私聊，按当前问题相关性优先、记录时间次之召回；保留群、消息与记录时间来源，不写成私聊事实。重生成使用当时的问题，不受之后的话题干扰。删除群记忆或群聊后，不再作为上下文提供。

## 本机后台调度

一键启动脚本同时启动 `scripts/group-worker.mjs`，也可在项目目录运行 `npm run groups:worker`。每分钟请求本机 `/api/proactive/groups/run`；授权只取本机 cron secret，不向浏览器暴露。分页检查群聊，群设置默认关闭主动生成，需用户开启。关闭网页后仍可保存主动消息；电脑或服务关闭则停止。

调度进程有独占锁，重复启动不会启动多份实际调度。任务串行执行；模型响应较慢时检查会延后，间隔表示最早触发时间。调度端点不返回聊天内容；日志仅记录检查数量、结果及固定错误文案。切勿把本机任务当成已部署的公网通知服务。

回复使用持久化领取记录：同轮已完成的回复可幂等重读；在途请求不能重复领取，模型失败或服务重启后可恢复。单人物单轮最多尝试三次，达到上限后暂停该轮，用户发送新消息后开始下一轮，避免后台无限重试消耗额度。

## 人物表达与自然接话

参考 SillyTavern 的 [当前发言者角色卡](https://docs.sillytavern.app/usage/core-concepts/groupchats/) 和 [人物示例及角色提示](https://docs.sillytavern.app/usage/core-concepts/characterdesign/) 组织方式，每次只放当前人物完整设定；其他成员仅提供公开姓名、群内关系和可见发言。人物自己的历史使用 assistant 纯文本，其他人的消息保留姓名、身份和原始时间标注，降低把同伴语气当作自己的风险。用户本轮问题与最近发言者分别保留，后发言的人补充自己的观点，不依次复述前一位的答案。私聊也以具体人物设定优先，不默认使用咨询师式的共情、建议、追问和总结。

回复长短由设定和当下内容决定，允许简短应答、不同意见与自然结束；不通过编造共同经历或当前生活来填充。记忆仍遵守原有知情与私聊授权，不扩大其他人物的信息读取范围。自动接聊时不选刚发言的人回复自己；没有新点名的「收到、哈哈、先这样、晚安」等明确简短收尾可以结束这一段，不再强行接力。新用户消息可重新开始对话。

生成后的独立检查对最近可见消息检测整段近似重复、抄取群友末句和多次相同长开头。正常短回应、共享姓名/短事实和带实质新看法的明确引用保留；用户明确要求复述时也可复述。这是保守的词面检查，不保证识别所有同义复述或语义空泛。

只有明确命中重复时，候选不展示、不保存，最多额外调用同一模型一次重写；两次共用原来的 45 秒窗口，原设定、记忆权限及安全规则均保留。普通回复仍一次调用，失败供应商请求不因为质量检查自动重试。两次仍重复则保留原有失败恢复流程，不拼接固定替代话。每次已发生的调用单独记录用量，丢弃候选记为 error / repetition，重写成功记为 success；既有单人物单轮三次领取恢复上限保留，因此极端情况下最多六次模型调用，不是无限重写。

## 结构与验证

- 数据契约：`src/lib/groups/types.ts`。
- 持久化及业务：`repository.ts`、`service.ts`、`validation.ts`。
- 人物生成：`generation.ts`；重复检查：`reply-quality.ts`；私聊衔接：`private-context.ts`。
- 用户接口：`/api/groups`、`/api/groups/[groupId]`；仅可访问本人群聊。
- 界面：`src/components/group-workspace.tsx`、`src/app/groups/`。
- 迁移：`prisma/migrations/20261113010000_group_workspace/`，增量创建独立表，不改动已有私聊数据。
- 导出包含脱敏群聊快照；删除账号级联清理。

`npm run qa:groups` 运行不联网的生成/业务验收；`npm run e2e -- tests/e2e/group-flow.spec.ts` 运行隔离浏览器验收。`GROUP_DATABASE_QA=1 npm run qa:groups:postgres` 在自己的临时 schema 中验证迁移、重连、所有权、CAS 和级联，再清理自身 schema。

## 首版容量与边界

每群最多 12 位人物、1000 条消息、100 条共同记忆及约 1 MB 状态。达到容量明确提示，不静默丢弃历史；跨群搜索、自动归纳记忆候选、长期归档与人物之间关系数值演化暂未实现。群内关系通过可编辑文字设定。每位发言人物通常调用一次模型，仅命中重复时允许一次额外重写；实际用量归入群回复或群主动分类，失败及丢弃候选也按已返回用量记录。mock 流程不代表真实模型的多人表现。
