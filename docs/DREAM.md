# 入梦：人物校准与能力演出

## 产品规则

本模块采用用户确定的二创框架：以「生生不息」创造人物初形，以「入梦」进入其意识空间，在对话、选择和纠正中完善表达习惯。原著能力与项目机制分别记录，避免把产品规则冒充原著。

- 原著参考：回响与信念、记忆；巨钟与显示屏；「生生不息」的创造能力；「入梦」的梦境能力。
- 项目二创：初形尚未清晰、入梦校准设定、光团显影、梦境门、悬浮片段、保存并醒来。
- 来源：[番茄原作目录](https://fanqienovel.com/page/7143038691944959011)、[第618章《入梦》公开片段](https://fanqienovel.com/reader/7291278167665279550)、[中国作家网作品介绍](https://www.chinawriter.com.cn/n1/2024/1213/c404027-40381608.html)、[能力与钟屏机制整理](https://wapbaike.baidu.com/item/十日终焉/63368747)。公开正文片段不是全章通读证明；光团、门户镜头不宣称为原著固定特效。

## 使用路径

1. 创建人物后发动生生不息，或从已有聊天页点击「入梦」。
2. 点击「进入梦境」，创建该人物的独立草稿并播放一次入场。已有草稿直接恢复工作区，刷新后也不会要求再次发动能力。
3. 用推荐情境或自拟问题开始。对比选择一次生成三条候选；自由试聊一次生成一条。每轮可选择更像的人物回应、选择「都不像」，或填写自己的纠正。
4. 指定反馈适用范围：平时如此、类似情境、偶尔表达。归纳的片段需要用户核对、修改、勾选确认；不把一次偏好扩大为永久性格。
5. 记录反馈后直接继续下一轮，不重播动画。编辑过的底稿与片段在下一次生成或记录反馈前自动暂存；不会自动调用下一轮模型，也不会自动应用正式人物设定。手动保存草稿仍可使用。
6. 主动点击「结束入梦」，核对基础性格、说话方式与已确认片段，预览与当前人物设定的变化，确认后应用并醒来。每次梦境最多保留二十段，达到容量后提示整理并结束。
7. 可暂存后离开、明确舍弃本次梦境，或预览并恢复已保存的设定版本。

## 数据与模型边界

- 梦境轮次、反馈、候选和版本与正式 Message、Memory 隔离。候选台词、测试场景不成为共同经历，也不改变关系背景。
- 仅更新人物 personality 与 speakingStyle；姓名、身份、背景、称呼、主动频率、正式聊天和长期记忆不由入梦覆盖。
- 应用前后保存版本，恢复需要二次确认；多标签修订号冲突返回 409。正式人物在其他页面更新后，旧梦境不能静默覆盖。
- 重新读取保留未提交的情境与纠正；若原轮次已更新，保留纠正原文供人工核对。正式人物版本冲突时，可以显式核对最新基准，保留梦境草稿后再次预览应用。
- 所有访问绑定登录用户与人物所有权。新表级联归属人物/账号；导出包含该用户的梦境状态，并沿用现有脱敏。
- 使用现有多供应商 BYOK 接入。三条候选共用一次模型请求；反馈归纳单独记录用量。真实模型失败明确报错，不用模板伪装成功。
- 无模型配置时标明「本地演示」；只能演示流程和整理用户主动填写的纠正，不能证明人物模仿质量。
- 每轮内容、片段长度、历史轮次及版本均有上限；长期记忆另行管理。

## 两种入场

| 阶段 | 生生不息 | 入梦 |
| --- | --- | --- |
| 起点 | 原巨钟、旧城广场 | 同一广场，人物意识尚未展开 |
| 宣告 | 我看到了【生生不息】的激荡 | 我听到了【入梦】的回响 |
| 能力显现 | 暖白光团增强，再衰退，长发长裙的黑色人影留下 | 建筑重影、倒影，门开启并逐步进入 |
| 收尾 | 人物姓名与正式对话 | 梦境对话与待确认片段 |

共享入口通过 `src/lib/ability-events.ts` 分发；默认开场与原有重播事件兼容。完整/短版、静音、跳过、Esc、减少动态、图像失败回退和焦点返回由同一组件负责。钟击保持洪亮，入梦改变余响空间。动画只呈现状态，不创建数据或调用模型。

`/echoes` 是可独立访问的回响录，提供两种演出预览及二创规则说明；设置页「外观」可进入。动画不在每轮反馈后重复播放。

生生不息剪影使用[余念安人物参考图](https://rubii.ai/profile/Rubii__f387c11b-386c-4bc1-80c2-9bb618b3dc65)，由图片编辑工具提取人物，保留原图的长发、提裙姿态、弧形裙摆与交错双腿，去除纸底、红色投影和文字。透明 PNG 作为遮罩，以统一黑色呈现；不是手工简化的几何人形。来源与生成提示保存在 `design/references/yu-nianan-silhouette.md`。该图为网络人物图，不作为原著服装的权威说明。

## 实现与验收入口

- 页面：`src/app/dream/[companionId]/page.tsx`、`src/components/dream-workspace.tsx`。
- 业务：`src/lib/dream/`；接口：`/api/companions/[companionId]/dream`。
- 新增持久化结构使用可审阅的 Prisma 增量迁移；有数据库的环境先执行迁移，不能以临时内存掩盖缺表。
- 自动验收重点：所有权、同源、草稿隔离、确认应用、版本恢复、冲突、模型错误脱敏、刷新续接与手机布局。
- 当前实测日期、结果及限制统一记录于 [MVP_STATUS.md](MVP_STATUS.md)。
- `npm run qa:dream` 为无网络服务与费用计量回归；`DREAM_DATABASE_QA=1 npm run qa:dream:postgres` 在独立临时 schema 运行全部版本迁移、断开重连、应用/恢复、事务回滚及删除级联，结束后只清理自身临时 schema。
