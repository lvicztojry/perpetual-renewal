# 电脑与手机局域网试用

电脑运行应用，手机连接同一 Wi-Fi 后访问电脑的局域网地址。两端登录原来的同一个账号，继续使用原数据库与已保存的模型配置；不需要新服务器、域名或重新注册账号。

## 启动

双击根目录「局域网启动生生不息.bat」。窗口会显示手机访问地址，并在电脑打开相同页面。原「启动生生不息.bat」保留仅本机启动方式。

脚本优先选择有网关的无线网卡私有 IPv4；每次启动重新检测并写入忽略文件 `.tmp-lan-address.txt`。多个网卡选择不符时，可运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-local.ps1 -Lan -LanAddress 192.168.1.20
```

参数地址必须属于本机且为私有 IPv4。若已有仅监听 localhost 的旧服务，先关闭原服务再启动；脚本不会强行终止其他进程。电脑需要保持开机，关闭服务后手机无法连接。更换 Wi-Fi 或 IP 后需要重启服务并使用新地址。

## 配置边界

仅该启动进程设置 `AUTH_APP_URL` 为当前局域网 URL，使验证/找回链接使用手机可访问地址；不修改 `.env.local`，也不将凭据放入脚本。已读、群聊、入梦等写入接口也认可这个明确配置的应用来源，避免 Next 内部主机名与手机地址不同而返回 403。额外开发来源只在 development 下使用明确白名单，生产环境忽略它；不会信任任意 Host/Forwarded 请求头。Next 开发资源同样只额外允许当前地址及 localhost，不使用通配符。

后台群调度仍通过电脑本机地址调用原接口。未关闭防火墙、未设置路由器公网映射；如同一 Wi-Fi 有设备隔离，网络本身可能阻止访问。仅用于可信局域网试用：HTTP 不提供 TLS 加密。手机浏览器的录音、PWA 安装等安全上下文能力需要另行配置 HTTPS，不能据文字聊天可用推断全部原生能力可用。

私聊和群聊的消息关联 ID 已兼容没有 `crypto.randomUUID` 的 HTTP 环境，使用 `getRandomValues` 生成，保持服务端幂等要求。测试入口为 `npm run qa:auth`、`npm run qa:sync`；实机进度见 [MVP_STATUS.md](MVP_STATUS.md)。

## 手机聊天

群成员和群背景收在顶部「群简介」中，按需展开；消息区单独上下滚动，输入区随可视屏幕高度调整。成员与设置、群记忆在小屏幕以侧栏覆盖显示，关闭后回到聊天；展开简介或成员选择也不会将输入区推出屏幕。手机打开某段对话并停留在最新消息处时，应用会保存已读状态并更新角标，返回列表后无需再次点击清除。上翻历史、联系人列表或切到后台时，不确认尚未展示的新来信。
