# 跨端消息与未读

本模块复用同一账号的服务端数据。实际验收范围见 [项目状态](MVP_STATUS.md)，不将两个浏览器环境或手机尺寸测试称作实体手机与电脑完整互通。

## 使用体验

私聊在前台约每 7 秒获取当前会话，窗口恢复焦点、联网或从后台返回时立即检查。群聊保留原有前台刷新；本地发送、回复生成及管理操作忙碌时，群详情刷新可能暂缓。联系人列表与群列表也会刷新，不覆盖仍在编辑的输入和设置草稿。

服务端消息快照可以移除另一端已删除的消息，同时保留本页尚未确认的发送气泡；晚到的旧请求不能抹掉已发送的新消息。用户上翻阅读时不强行滚回底部；主动发送或切换人物后跟随最新消息。

未读角标使用青铜主题，零条隐藏，大于 99 显示 99+。只有页面处于前台、聊天区域可见且位于最新位置时，才确认当前已加载的来信；不依赖手机浏览器可能错误报告的 `document.hasFocus()`。手机联系人列表、后台页面和打开管理面板不会自动清空聊天未读。打开已选人物的聊天也会立即检查，不必等待轮询；新消息到达时排队确认，不取消已在提交的回执。每批确认后重新读取未读数量，晚到的旧查询不能恢复旧角标；网络失败继续重试，不直接在本机伪造清零。这里记录的是本应用的阅读确认，不能证明用户实际阅读了每个字。功能启用前没有已读记录的历史来信也会计入未读，打开相应对话后确认。

每个端未发送的输入仍属于该页面，不上传为共享草稿；当前页面内可在重新登录原账号后续接，关闭页面后的草稿恢复尚未实现。账号切换会隐藏旧工作区，避免把旧输入带入新账号。网络失败保留已有内容并重试，不把同步失败等同于未读清零。

## 服务端规则

- `GET /api/sync/inbox`：严格登录，仅返回当前用户 ID、私聊/群聊线程 ID、未读数量及检查时间，不返回正文，不触发模型。
- `POST /api/sync/read`：已登录且来源可信；允许请求 URL 或部署明确配置的 `AUTH_APP_URL` 对应来源，开发模式还允许 `AUTH_DEV_ALLOWED_ORIGINS` 中的精确来源，处理 Next 内部主机名与手机局域网地址不同的情况。缺失/无效 Origin、外站来源与 cross-site 元信息仍拒绝，不从 Host/Forwarded 请求头或私有网段通配符建立信任。传 scope、threadId、实际消息 ID，每次最多 200 条且请求体最多 16 KiB。整批验证，外人、跨线程、已删除或无效消息不能造成部分确认。
- 按明确消息 ID 幂等记录，不用客户端时间或时间游标。因此同毫秒、倒序或晚到的消息不会被旧确认吞掉。
- 数据库使用唯一约束与事务，删除账号、人物、会话、群或私聊消息时级联清理；内存试用保持同样的删除行为。数据库失败不切换成另一份内存已读状态。
- 账号导出包含有效线程中已确认消息的标识，不包含额外正文或凭据。SQL 数据参数与 schema 标识分别安全处理，隔离测试只访问自己的临时 schema。

## 验证入口

`npm run qa:sync` 运行轮询/快照状态机与实际回执核心测试；`npm run e2e -- tests/e2e/sync-flow.spec.ts tests/e2e/mobile-chat.spec.ts` 验证双浏览器、手机联系人列表、草稿保留、删除同步、账号切换及旧 GET 晚到，以及手机无焦点报告时私聊/群聊的已读落库和返回列表后的角标。默认使用隔离 memory/mock 服务。手机布局专项还覆盖长群名、长简介、成员选择、窄屏、可视视口缩小、上翻及面板开关；模拟键盘视口变化不等同于每种实体手机键盘均已验收。

来源回归包含内部请求 URL 为 localhost、浏览器 Origin 为已配置 LAN 地址的真实 POST 处理器测试，覆盖私聊和群聊确认后的未读归零及拒绝请求不写入；`npm run qa:auth` 包含共用来源校验的独立边界测试。浏览器经 LAN 地址访问的隔离验证和实体手机反馈另记于项目状态，不能用 localhost 通过替代 LAN 验收。

真实 PostgreSQL 专项为 `npm run qa:sync:postgres`，要求调用进程显式注入数据库配置并设置 `MESSAGE_SYNC_DATABASE_QA=1`。脚本只创建、迁移、使用和删除自己的随机临时 schema，不自动读取环境文件，也不触碰真实聊天。
