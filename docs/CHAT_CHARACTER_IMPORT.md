# 从聊天记录创建人物

入口：工作台侧栏“从聊天记录创建”，路径 `/create-from-chat`，需要登录。

## 使用流程

1. 粘贴或选择 TXT、JSON、JSONL 文本记录，在本地识别说话者。
2. 明确选择目标人物和用户自己，核对双方原话预览。
3. 使用用户 vault 或服务端 fallback 配置的模型，提炼姓名、关系、称呼、性格、表达习惯、背景、原话和共同经历。
4. 编辑核对草稿。原话样例只保留能在目标人物抽样消息中核对的内容；其他特征和经历仍可能推断错误，需要用户确认。
5. 临时试聊，支持继续对话。修改设定会清除旧试聊验证状态，需重新试聊。
6. 确认后创建人物，保存语气样例及已核对的共同记忆，返回正式聊天。

## 范围与限制

- 文件最多 1 MiB，文本最多 200,000 字符、4,000 条有效消息、100 位参与者。超限明确拒绝，不无提示截断。
- 支持带姓名的普通文本、常见 QQ/微信文本时间头，以及通用 JSON 数组、`messages` 数组和 JSONL。JSON 消息需包含 speaker/sender/name/from 与 content/text/message，或明确的 user/assistant role。
- 不直接解密或读取微信/QQ 二进制数据库、压缩包，也不自动抓取平台资料。不同导出工具格式存在差异，用户需核对说话者和解析提示。
- 仅选定双方参与提炼，其他说话者不发送给模型。长记录跨时间抽样，最多约 160 条消息、24,000 字符的序列化样本；长消息会缩短，页面显示本次实际条数与提示。
- 未配置可用模型时，只按目标原话整理本地基础草稿，不推断性格或共同经历；临时回复明确标注本地预览。真实模型失败返回错误，保留页面内容供重试。
- 本功能使用模型上下文模仿与记忆检索，不训练或微调模型。共同记忆沿用已有的词面相关检索，不保证每轮都提供全部回忆。

## 存储与隔离

选择与解析在浏览器完成；点击提炼后文本提交给本应用，服务端抽样、移除疑似密钥后才调用用户供应商。原始文件、原始全文和临时试聊不写入数据库、日志或浏览器持久存储。模型使用量只记录 provider/model、token、耗时和状态等元数据。

确认前不会创建人物。确认后通过现有仓库一次创建人物、会话、关系状态及初始 active 共同记忆；PostgreSQL 使用 Prisma 嵌套创建，memory 实现保持同一返回结构。后续可编辑人物资料与记忆，数据沿用账号隔离、导出和删除能力。新人物默认关闭主动回响，用户可在人物资料中开启。

## 验证

`npm run qa:character-import` 检查解析、抽样、归属、脱敏、草稿验证、真实逻辑假供应商和临时试聊；已接入 CI 与 verify-local。

浏览器验证位于 `tests/e2e/chat-character-import.spec.ts`：本地导入/核对/试聊/保存闭环，用户 BYOK 假供应商与失败重试，输入及登录保护；包含 320px 实际截图。全量浏览器回归已通过 43 项，真实供应商未在本轮自动调用。

本轮结果：解析 14 组；人物服务 23 个案例、344 个断言；完整 memory API smoke 94 项；生产构建、生产访问保护、lint、文档与密钥检查通过。PostgreSQL 初始记忆使用现有模型的嵌套写入，本轮未新增迁移，也未向真实用户账号写入测试人物。
