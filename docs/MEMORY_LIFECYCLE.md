# 记忆变化与纠错

本页描述记忆模块契约；实际验收日期和范围统一记录在 [项目当前状态](MVP_STATUS.md)。人物表达与性格的校准仍集中在 [入梦](DREAM.md)，普通聊天消息不增加评价或训练入口。

## 使用方式

在人物的「记忆」面板核对候选、编辑事实、归档旧信息或查看变更历史。新事实已经建立后，可在旧的生效记忆中选择「用另一条记忆更新这个事实」，预览两条完整内容，点击「确认新事实生效」才提交。

一次替代会同时归档旧事实、启用新事实，并分别记录各自的修改前后内容。人物、用户、两条记忆的版本任一不匹配，整次操作失败；数据库写入历史失败也回滚两条事实。被替代的旧事实不能通过普通「恢复」意外重新生效；确需反向替代，必须从当前生效事实重新核对两条记忆。

普通内容修改和候选确认也携带用户读到的版本；另一端修改后，旧版本返回冲突，需重新读取后确认。历史按时间与稳定游标分页，不凭编辑时间推断事件发生时间，也不自动把同主题的新陈述视为旧事实的终结。

## 遗忘的实际范围

删除记忆会清除该条长期记忆的正文、来源消息关联和它的变更历史，保留不含正文的已遗忘标记，不能从历史恢复。它不删除原始聊天消息，也不保证从当前对话上下文、用户已下载的备份或其他独立记忆中清除同一话题。确认框会明确提醒原始消息仍保留。

历史记录从功能启用后的修改开始，不能还原之前已经覆盖的编辑。来源消息和人物设定的删除遵循各自现有流程。

## 导出与账户清理

导出中的长期记忆与其历史使用同一个一致性快照：数据库以 RepeatableRead 事务读取，内存模式在同一同步操作中复制。已遗忘、其他用户和失去所属记忆的历史不会进入新快照；快照完成后发生的修改不会追溯改写已经生成或下载的文件。导出的聊天记录仍可能含有原始内容，导出不表示全话题遗忘。

每条历史只保存它自己的记忆正文及关联 ID，不在另一条事实的历史里复制旧正文。导出继续执行现有密钥及调试信息脱敏。删除人物或账号会同时清理其记忆历史。

## 时间依据与自然表达

私聊、重生成、群聊和主动回响提供当前运行时刻及配置时区；时区缺失或非法时明确使用 UTC。私聊与主动提示词为选中的原始消息提供位置对应的发言时间索引，历史摘录也可保留原始消息时间和来源 ID。两者只使用事实内容后的剩余预算，不为时间字段挤掉最新用户消息或历史事实。群记忆及获准使用的私聊记忆保留结构化收录/编辑时间和来源，不再只剩一段纯文本。

这些日期不是事件发生日期。记忆今天导入、确认或编辑，都不能证明原话中的「明天」指向今天之后；相对日期需要可核对的原始消息时间及原话，当前设置时区也不能冒充历史时区。缺少依据时保留未知，不自动认定计划已经完成、取消或仍未完成；模型自然提起曾聊过的事、询问后续，日常不向用户输出内部字段。

主动选题使用保守文本规则：相对日期和结果不明的具体计划不直接充当当前事件或已发生的共同回忆；含旧年份的持续事实不会仅因年份被排除。「我没有兄弟姐妹」「不喜欢猫」「希望你叫我阿明」等否定事实、互动诉求和周期偏好，不因否定或愿望词而整体排除。过去经历须有明确过去线索，表达仍归因于已知记录，不补全共同参与或结局。规则可能跳过部分可用记忆，不等于完整自然语言时间解析，也不会自动改变记忆状态。

## 接口与持久化

- `PATCH /api/memories/:id`：公开的编辑、确认和归档请求必须传 `expectedUpdatedAt`；缺失或非法为 400，过期为 409。
- `DELETE /api/memories/:id`：支持可选的 `expectedUpdatedAt`，界面始终传入版本；为兼容已有调用保留无请求体删除，非法 JSON 返回 400。
- `GET /api/memories/:id/history?before=...`：独立登录和所有权校验，默认每页 20 条，返回 `nextCursor`。
- `POST /api/memories/:id/history`：仅同源请求；`action: supersede` 同时传旧事实版本、`replacementId` 和新事实版本 `replacementUpdatedAt`；按真实流量限制请求体大小。

所有响应为 private/no-store；数据库错误不回退成另一份内存数据。变更由版本迁移 `20261117010000_memory_revisions` 新增 MemoryRevision 表和替代关联，不改写既有事实正文。

## 验证入口

- `npm run qa:memory-lifecycle`：实际规划器、原子应用、来源/版本/人物边界、历史清理与导出快照。
- `npm run e2e -- tests/e2e/memory-lifecycle.spec.ts`：API、冲突、非法请求、导出及手机记忆面板闭环；默认模拟供应商与内存存储。
- `MEMORY_DATABASE_QA=1 npm run qa:memory:postgres`：显式启用后，在自建临时 schema 应用版本迁移，验证重连、真实事务回滚、两个客户端竞争、并发导出/遗忘和账号级联清理，最后删除自己的临时 schema。

上述手机窗口和两个数据库连接的验收，不等于已经验证实体电脑与手机之间的完整互通、离线同步或独立原生应用。
