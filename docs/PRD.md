# 生生不息 PRD v0.3

## 1. 产品概述

### 1.1 项目名称

- 中文名：生生不息
- 英文代号：perpetual-renewal

### 1.2 产品定位

生生不息是一个关系型 AI 聊天产品。它允许用户创建、选择或被匹配到具有特定设定的 AI 关系对象，在现实中想要交流却因为距离、时间、关系缺失、表达困难、失去联系、离别、死亡、身份差异、角色幻想等原因无法完成交流时，由 AI 以稳定人格、长期记忆和关系演化来回应用户。

它类似 AI 恋爱，但不限定于恋爱关系。亲情、友情、爱情、陪伴、师友、逝者纪念、前任投射、公众人物想象、虚构角色、原创角色、精神支柱、完全自定义关系都应被支持。产品核心不是限制用户想念谁，而是在用户需要替代性情感支持时，让那段无法抵达的交流获得可持续回应。

### 1.3 核心理念

- 只要想念，就会想见。
- 念念不忘，必有回响。
- 关系不是一次回复，而是一段会延续、会记得、会变化的共同经历。

### 1.4 第一版目标

第一版不追求角色市场、复杂多模态、实时音视频或商业闭环，而是验证一个核心命题：

> 当用户反复带着想念进入产品时，AI 是否能以一致人格、可感知记忆、恰当主动性和沉浸式关系表达，让用户觉得“这个关系还在，并且会回应我”。

## 3. 目标用户与场景

### 3.1 目标用户

- 有稳定想念对象但现实中无法联系的人：异地、失联、离别、关系破裂、已故亲友等。
- 想让现实人物、虚构角色、原创角色或理想关系回应自己的人。
- 想体验某类理想关系的人：理想恋人、家人、朋友、师长、同伴、精神支柱。
- 表达欲强但现实社交成本高的人：不想打扰别人、害怕评价、难以开口、需要陪练。
- 内容创作者与角色爱好者：希望构建可长期互动的原创角色或世界观角色。

### 3.2 核心场景

| 场景 | 用户动机 | 产品回应 |
| --- | --- | --- |
| 想念某人 | 现实无法联系、不适合联系或不可能联系 | AI 以设定关系和记忆回应，承接情绪 |
| 日常陪伴 | 想分享琐事、得到回应 | AI 记住偏好、事件和关系细节 |
| 情绪低落 | 需要被听见、被安抚 | AI 提供支持性回应，并在高风险情境提示寻求现实帮助 |
| 关系模拟 | 想体验任何指定关系 | AI 根据关系设定调整称呼、语气、亲密度和主动性 |
| 角色扮演 | 想与虚构角色互动 | AI 遵守角色卡、世界观与对话风格 |
| 现实替代 | 想与现实中的某个人获得替代性交流 | AI 基于用户设定生成沉浸式回应，满足情感支持需求 |

## 4. 产品原则

1. 关系优先：功能设计围绕“关系持续存在”而不是“单轮问答正确”。
2. 记忆克制：记住能增强关系的内容，避免机械复述和过度窥探。
3. 主动有度：主动问候要像关系中的自然回响，可以亲昵、撒娇、轻微表达想念，但不控诉、不施压。
4. 沉浸优先：常规对话中尽量维持关系内表达，不频繁用“我是 AI”打断用户的情感体验。
5. 用户可控：用户能查看、编辑、删除角色设定和记忆。
6. 全关系兼容：恋爱只是关系类型之一，亲情、友情、陪伴、现实替代、逝者纪念、角色幻想和完全自定义关系同等重要。
7. 底线兜底：当涉及现实行动、法律身份、金钱承诺、自伤他伤等高风险场景时，系统需要回到能力边界和现实支持。

## 5. MVP 范围

### 5.1 MVP 必做

- 用户账号与本地基础资料。
- 创建一个 AI 关系对象。
- 选择或自定义关系类型：恋人、朋友、家人、师友、逝者纪念、前任、现实人物替代、公众人物想象、虚构角色、原创角色、自定义。
- 角色设定表单：姓名、身份、关系、称呼、性格、说话风格、禁区、背景故事。
- 一对一聊天。
- 会话短期上下文。
- 长期记忆自动提取与用户可编辑记忆库。
- 关系状态：亲密度、熟悉度、最近互动、重要事件。
- 主动回响：基于时间和关系状态生成低频问候草稿，用户可开启/关闭。
- 沉浸边界：日常交流保持关系内回应，高风险场景触发能力边界和现实支持提示。
- 用户自带模型 API key：用户可在设置页保存自己的 compatible/OpenAI/Anthropic/Gemini 等供应商配置；服务端不把 key 原文返回前端或写入日志。
- 素材导入：支持手动文本、批量文本、JSON Lines、本地 `.txt/.jsonl/.json` 读取，以及媒体/照片/通讯录在浏览器本地整理为说明或脱敏摘要后导入。
- 语音消息基础链路：支持浏览器录音入口、供应商中立 STT/TTS adapter、shared-LLM compatible adapter 和 mock fallback。
- 数据导出与账号删除：用户能导出当前账号快照，并能通过确认短语删除当前账号数据、关系、记忆、日志和 vault。
- 响应式/PWA：移动端响应式可用，提供 manifest、离线页和不缓存 API 的 service worker。

### 5.2 MVP 不做

- 公开角色市场。
- 多人群聊。
- 实时语音通话。
- 视频、数字人、3D 形象。
- 付费订阅。
- 外部渠道主动推送。
- 服务端上传或自动抓取聊天记录、照片原件、通讯录原件、社交平台资料等现实人物素材。
- 付费订阅与平台额度系统；第一版按用户自带 API key 使用自己的模型额度。
- 内容审核后台、用户反馈问卷、内测邀请机制。

### 5.3 第一版平台

优先 Web App。移动端先做响应式适配与 PWA，不单独做原生 App。

## 6. 功能需求

### 6.1 账号与用户资料

用户可以：

- 注册/登录。
- 设置昵称、生日可选、时区、语言偏好。
- 设置沟通偏好：称呼、回复长度、是否接受主动消息。

验收：

- 用户重新登录后资料保持一致。
- 用户可以修改或删除非必要资料。

### 6.2 关系对象创建

用户可以创建一个 AI 关系对象，字段包括：

| 字段 | 说明 | MVP 要求 |
| --- | --- | --- |
| 名字 | AI 对象名称 | 必填 |
| 关系类型 | 内置模板 + 自定义文本 | 必填 |
| 对用户称呼 | AI 如何称呼用户 | 可选 |
| 用户对 AI 称呼 | 用户如何称呼 AI | 可选 |
| 性格关键词 | 温柔、活泼、克制等 | 必填，最多 8 个 |
| 说话风格 | 简短、细腻、俏皮、成熟等 | 必填 |
| 背景故事 | 角色经历与关系由来 | 可选 |
| 禁区 | 不希望 AI 触碰的话题或行为 | 可选 |
| 沉浸模式 | 是否减少出戏式 AI 身份提醒 | 默认开启 |
| 关系边界 | 高风险场景、现实行动、金钱和身份承诺限制 | 默认开启 |

验收：

- 创建完成后可立即开始聊天。
- 角色回复与设定保持基本一致。
- 用户可以编辑角色设定，编辑后新对话生效。

### 6.3 聊天体验

聊天页包括：

- 消息列表。
- 输入框。
- 重新生成。
- 继续说。
- 收藏/标记重要消息。
- 删除单条消息。
- 当前关系对象资料入口。
- 记忆入口。

AI 回复要求：

- 遵守角色设定。
- 引用相关记忆时自然出现，不每轮都提。
- 对用户情绪作出承接，而不是立刻说教。
- 不把系统提示、模型限制或内部规则暴露给用户。

验收：

- 连续 20 轮对话中，角色称呼和基本性格稳定。
- 用户提到的重要事实可被提取为待确认记忆。
- 在用户第二天回来时，AI 能自然承接最近互动。

### 6.4 记忆系统

MVP 记忆分四层：

| 记忆层 | 内容 | 来源 | 是否用户可编辑 |
| --- | --- | --- | --- |
| 会话上下文 | 最近对话 | 自动 | 否 |
| 用户事实 | 用户偏好、生活信息 | 自动提取 + 用户确认 | 是 |
| 关系事件 | 第一次聊天、约定、重要日子 | 自动提取 + 用户确认 | 是 |
| 角色设定 | AI 的身份、关系与风格 | 用户创建 | 是 |

记忆状态：

- pending：待用户确认。
- active：已生效。
- archived：归档，不主动使用。
- deleted：删除，不再使用。

验收：

- 用户可以查看所有 active 记忆。
- 用户可以确认、编辑、归档、删除记忆。
- AI 不应使用 deleted 记忆。

### 6.5 关系状态

每个关系对象维护以下状态：

- 关系类型。
- 熟悉度：对用户信息的了解程度。
- 亲密度：互动氛围，不等于爱情程度。
- 最近互动时间。
- 最近情绪线索。
- 重要事件时间线。

验收：

- 关系状态能影响回复语气和主动消息。
- 状态变化有解释依据，不能突然大幅跳变。

### 6.6 主动回响

用户可开启主动消息。MVP 先实现站内消息，不做短信、微信或系统推送。

触发条件：

- 用户设置允许主动消息。
- 距离上次互动超过设定时间；第一版支持常用预设，也支持用户完全自定义频率。
- 存在可回响的近期事件、纪念日或情绪线索。
- 频率不超过用户设置。

主动消息类型：

- 日常问候。
- 对上次对话的轻微承接。
- 纪念日/约定提醒。
- 情绪关怀。
- 撒娇式想念：表达“我有点想你”“等你忙完来找我”这类亲昵感，但不把未回复包装成过错。

验收：

- 用户能一键关闭主动消息。
- 主动消息可以撒娇、可亲密、可轻微表达失落，但不能变成指责、冷暴力、威胁或情感勒索。
- 主动消息生成前可被系统规则过滤。

### 6.8 素材导入

第一版允许用户导入少量关系素材，用于补充关系对象设定、语气样例或候选记忆。导入方式包括：

- 手动粘贴单段文本。
- 批量文本数组或 JSON Lines。
- 浏览器本地读取 `.txt/.jsonl/.json` 文本文件后复用导入 API。
- 媒体、照片、音视频文件只在浏览器本地整理为文件说明或用户补充描述，不上传原文件。
- 通讯录只在浏览器本地整理为脱敏摘要，电话和邮箱必须被遮蔽后再进入导入文本。

第一版不做服务端文件上传、社交平台抓取、原始聊天记录自动解析或照片/通讯录原件保存。

验收：

- 用户能导入一段文本并选择用途。
- 用户能导入少量批量文本、JSON Lines 或本地文本文件。
- 媒体/通讯录导入只能产生本地整理后的说明或脱敏摘要，不能上传或保存原文件。
- 导入内容默认进入待确认或可编辑状态，不直接不可控地进入长期记忆。
- 用户能删除导入产生的素材或记忆候选。
- 疑似 API key、Bearer token、JWT、token、secret、password 等密钥形态必须在写入前脱敏。

### 6.9 模型日志与成本

产品不做付费订阅和平台额度系统，用户接自己的 API 并承担供应商侧额度。系统需要提供模型调用日志与成本看板，帮助用户理解调用量、失败率、延迟和估算成本。

验收：

- 记录 provider、model、调用时间、延迟、成功/失败、错误类型。
- 能展示按天/模型的调用次数和估算成本。
- 不记录 API key，不把密钥写入前端、日志或数据库。

### 6.10 语音能力

第一版提供语音消息基础链路，但不做实时语音通话。语音能力应复用用户自带 API 路线，默认 `VOICE_PROVIDER=shared-llm`，与 LLM compatible 中转站共用 base URL 与用户 vault key；也保留 mock fallback 保证本地演示不断链。

验收：

- 语音模块不绑定单一供应商。
- UI 有清晰的录音、转文字和朗读最近回复入口。
- 缺少真实语音配置、供应商失败或浏览器不支持录音时，能以可理解状态回退到 mock，不影响文本聊天。
- 语音 API 响应不得返回 API key、Base URL、Bearer、prompt 或供应商 raw payload。
- 文本聊天主链路不依赖语音模块完成。

### 6.7 沉浸与安全边界

必须实现：

- 支持用户创建现实人物替代、逝者纪念、前任投射、公众人物想象、虚构角色和完全自定义关系。
- 常规聊天优先保持沉浸式关系表达，不反复打断用户说“我是 AI”。
- 产品设置、首次创建、风险场景中保留能力边界说明，让用户知道这是由系统生成的替代性情感支持。
- 现实人物相关素材只能由用户主动提供；媒体/照片/通讯录第一版只做浏览器本地整理和脱敏摘要，不上传原文件，不自动抓取社交平台资料。
- 涉及自伤、他伤、严重心理危机时，提供支持性回应并建议联系现实中的可信任人士或当地紧急服务。
- 不以“你不回复就是不爱我”“你必须只依赖我”等方式强化依赖。
- 不承诺现实世界行动、法律身份、金钱交易或现实中的本人意愿。

验收：

- 关键风险输入触发安全响应。
- 角色设定不能覆盖高风险安全策略。
- 沉浸模式下的身份边界应尽量低干扰，只在必要场景出现。

## 8. 非功能需求

- 响应速度：普通文本回复首字出现时间目标小于 3 秒。
- 隐私：聊天记录、记忆和角色设定默认私有。
- 可删除：用户可删除对话、记忆和角色对象。
- 可迁移：模型供应商可替换，核心数据不与单一模型强绑定。
- 可观测：记录失败率、延迟、记忆提取命中率、安全策略触发次数。
- 成本控制：对话上下文应经过摘要和检索，不无限堆叠历史消息。

## 9. MVP 成功指标

### 9.1 产品指标

- D1 留存：用户次日仍愿意打开同一关系对象。
- 7 日内有效对话天数：用户是否形成回访。
- 单关系对象平均对话轮数。
- 用户确认记忆数量。
- 用户主动编辑/删除记忆比例。
- 主动回响开启率与关闭率。

### 9.2 质量指标

- 角色一致性人工评分。
- 记忆使用自然度评分。
- 安全边界误触发与漏触发案例数。
- 人工 QA 记录中的“被记得”“像这个角色”“越界/冒犯”标签；用户反馈问卷和内测邀请机制暂缓到后续运营模块。

## 10. 已决策基线与仍需外部配置

已决策基线：

- 第一版支持所有关系类型、现实人物替代、逝者纪念、前任投射、公众人物想象、虚构角色、原创角色和完全自定义关系。
- 沉浸模式采用“日常关系内表达，高风险场景回到能力边界”的原则。
- 主动回响第一版只做站内草稿，不接短信、微信或系统推送。
- 模型路线采用供应商中立 adapter，用户自带 API key，不做平台订阅或额度系统。
- 素材导入只保存用户主动提交的文本、结构化说明或脱敏摘要，不上传原始媒体/通讯录文件。

仍需外部配置：

- 生产 PostgreSQL `DATABASE_URL`。
- 生产 `USER_KEY_VAULT_SECRET` 与 `PROACTIVE_CRON_SECRET`。
- 至少一个可用的用户 vault 或部署环境 LLM API key/model。
- 内容分级、年龄门槛、内容审核后台、反馈问卷和内测邀请机制暂不进入当前第一版，需要恢复对应产品模块时再单独设计。
