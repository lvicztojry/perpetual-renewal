# 主动回响的自然表达

每次到期先规划话题、参考记忆与长度，再使用当前用户的模型生成。手动生成默认一条草稿，与自动回响共享生成策略，但仍需手动发送。账号及人物开关、到期间隔、投递幂等规则仍生效。

## 人物与话题

人物性格、称呼、背景、说话风格和原话样例进入生成上下文。规划器轮换话题跟进、共同回忆、兴趣闲聊、打趣、想念和具体关心，不要求每轮复述最后一句话、提问或安慰。

只选当前用户和人物的 active 记忆，最多三条，每条最多 240 字；近期提供过的记忆降低优先级。过期或相对时间不明确的事情不作为当前事件跟进，过去的共同经历可以作为回忆。预选记忆不再被最后一句用户消息的关键词过滤掉。没有记忆时依据人物设定聊天，不编造共同经历或实时事实。

## 长短与重复

默认短/中/长表达权重约 50/35/15，目标 5–25、25–70、70–180 字，按人物风格调整，并参考近期生成记录避免连续三次同类表达。目标范围用于提示和质量约束，允许自然短句及一定下限余量。

近期主动消息及有效 assistant 消息用于本地重复检查。检查精确重复、文字近似、常见安慰表达和重复尾句；最多重写一次，两次调用共用 20 秒截止时间。此检查是有界的文字与短语规则，不是完整语义理解，仍需真实试聊评估。

## 失败与可见性

真实模型调用失败、两次结果仍为空/重复/不合适时，本轮不保存、不投递固定模板；页面通过检查结果显示原因，下次按现有检查节奏重试。mock 或缺少模型配置的演示模式保留演示模板，界面显示生成来源。安全边界响应沿用既有规则。

成功记录附带生成来源、意图、目标长度、所选记忆 ID、话题标识、实际字数和尝试次数，不保存内部规划提示词。模型调用用量按每次实际调用记录，质量重写可能额外消耗一次用户额度。无需数据库迁移。

## 验证入口

`npm run qa:proactive-scheduler` 覆盖调度、投递、人物生成、话题记忆轮换和重复检查；`npm run qa:proactive-availability` 覆盖开关、手动草稿和失败时不写入、不投递。浏览器既有主动回响用例用于验证可见状态及发送链路。

2026-11-05：上述两组模块回归共 161 项通过，浏览器定向回归 9 项、隔离 memory API smoke 94 项通过。生成器验证使用假供应商，不代表真实模型连续多轮的主观自然度评估。

本机仍需保持聊天页打开并选中人物；本改动没有增加关闭页面后的后台调度。
